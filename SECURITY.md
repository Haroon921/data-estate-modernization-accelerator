# Security Policy

## Supported versions

Security updates are applied to the latest version on the default branch.

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability or include secrets, customer data, tenant identifiers, or connection strings in any report.

Use GitHub's private vulnerability reporting feature:

1. Open the repository's **Security** tab.
2. Select **Advisories**.
3. Select **Report a vulnerability**.

Include the affected component, reproduction steps, potential impact, and any suggested mitigation. The maintainer will acknowledge a complete report as soon as practical and coordinate remediation and disclosure.

## Operational security

The repository contains starter assets and illustrative configuration. Before production use, apply your organization's security review, identity, network isolation, secret management, data classification, monitoring, backup, and incident-response requirements.
